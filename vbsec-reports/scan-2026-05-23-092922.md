### 🔴 [1] CRITICAL — HARDCODED-SECRET tại `" - Copy (2).env":1`

**Mô tả ngắn:** File env (có dấu CÁCH ở đầu tên) chứa Supabase `SUPABASE_SERVICE_ROLE_KEY` + `VITE_SUPABASE_ANON_KEY` (production: `supabase.ithoathodb.xyz`) đã commit vào git — gitignore không match được tên file có dấu cách.

**Tại sao nguy hiểm?**

`SUPABASE_SERVICE_ROLE_KEY` là **chìa khóa vạn năng** — bypass HOÀN TOÀN Row Level Security (RLS), cho phép đọc/ghi/xóa bất kỳ bảng nào trong toàn bộ project Supabase. Bao gồm: bảng `employees` (nhân sự, lương, CCCD hash), `thread_inventory` (toàn bộ tồn kho), `customer_orders`, `purchase_orders`... và có quyền `auth.admin.createUser()` (tạo tài khoản admin tùy ý).

Github có bot quét secret 24/7 (truffleHog, GitGuardian, gitleaks). Service-role JWT của Supabase có pattern dễ nhận biết (`eyJ...` với role=service_role). File đã ở trong git history hơn 10 commits → bất kỳ ai clone được repo (kể cả qua share branch riêng) đều thấy key này.

**Hacker khai thác như thế nào?**

1. Clone repo (hoặc thấy commit qua GitHub fork/scan)
2. Đọc file `" - Copy (2).env"` → extract `SUPABASE_SERVICE_ROLE_KEY`
3. Gọi REST API trực tiếp: `curl -H "Authorization: Bearer <SERVICE_ROLE_KEY>" https://supabase.ithoathodb.xyz/rest/v1/employees?select=*`
4. Dump toàn bộ database trong vài phút (employees, lương, CCCD hash, customer info, đơn hàng, tồn kho)
5. Tạo user admin: `POST /auth/v1/admin/users` với email + password tùy chọn → đăng nhập web app như admin thực sự
6. Cài backdoor: tạo function `SECURITY DEFINER` PostgreSQL hoặc INSERT vào `permissions` để duy trì access kể cả sau khi rotate key

**Code hiện tại (NGUY HIỂM)**

### 🟠 [3] HIGH — HARDCODED-SECRET tại `supabase/employees.sql:1`

**Mô tả ngắn:** File dump production data committed vào git — chứa bcrypt hash password, CCCD hash (mã căn cước), và **số điện thoại plaintext** của tất cả nhân viên.

**Tác động**

Bcrypt hash có thể brute-force offline (đặc biệt CCCD chỉ 12 chữ số → không gian tìm kiếm chỉ 10^12, GPU + bcrypt cost=10 có thể crack hết trong vài tuần). Số điện thoại plaintext là PII trực tiếp — vi phạm Nghị định 13/2023/NĐ-CP về bảo vệ dữ liệu cá nhân tại Việt Nam. Git history giữ file vĩnh viễn kể cả khi xóa.

**Cách sửa**

```bash
# 1. Thêm vào .gitignore:
echo "supabase/employees.sql" >> .gitignore

# 2. Xóa khỏi git + history:
git rm --cached supabase/employees.sql
git commit -m "security: untrack production data dump"
git filter-repo --path supabase/employees.sql --invert-paths

# 3. Force-rotate password tất cả employees (set must_change_password=true)
#    Đặc biệt audit xem có ai đã clone repo lấy hash chưa
```

### 🟠 [5] HIGH — HARDCODED-SECRET tại `Dockerfile.frontend:28-29`

**Mô tả ngắn:** Build ARG `VITE_SUPABASE_ANON_KEY` được promote sang ENV layer → key được bake VĨNH VIỄN vào image layer (visible qua `docker history --no-trunc`). Comment `# check=skip=SecretsUsedInArgOrEnv` lại tắt cảnh báo Docker built-in.

**Tác động**

VITE_ prefix có nghĩa key sẽ được inline vào JS bundle (đúng thiết kế cho anon key). Tuy nhiên ENV trong Docker image cũng giữ key đó ở layer metadata — nếu image được push lên public registry hoặc ai có access pull image → đọc được key. Anon key cần có **scope hạn chế** (RLS bảo vệ).

**Cách sửa**

```dockerfile
# Bỏ dòng ENV (giữ ARG only — Vite đọc ARG khi build):
ARG VITE_SUPABASE_ANON_KEY
# (xóa) ENV VITE_SUPABASE_ANON_KEY=${VITE_SUPABASE_ANON_KEY}
# (xóa) # check=skip=SecretsUsedInArgOrEnv
RUN npm run build  # Vite reads ARG at build time
```

### 🟠 [6] HIGH — MISSING-RATE-LIMIT tại `server/index.ts:73-122` (`POST /api/auth/ensure-auth-user`)

**Mô tả ngắn:** Endpoint **PUBLIC** (bypass authMiddleware) nhận `employeeId + password` từ caller bất kỳ và gọi `supabaseAdmin.auth.admin.createUser()`. KHÔNG có rate limit, KHÔNG có lockout. Distinct 404/403 responses cho phép enumerate valid employee IDs.

**Tác động**

Attacker brute-force: (a) enumerate danh sách `employeeId` hợp lệ (vd nhân viên có format `NV001`, `NV002`...) bằng cách phân biệt 404 vs 403, (b) với mỗi employee chưa có Supabase Auth user, tạo Supabase user với password ATTACKER chọn → đăng nhập web app như nhân viên đó. Đây là **account takeover** + **mass enumeration**.

**Cách sửa**

```typescript
// Thêm rate-limit middleware (vd hono-rate-limiter):
import { rateLimiter } from 'hono-rate-limiter'

const authLimiter = rateLimiter({
  windowMs: 15 * 60 * 1000,  // 15 phút
  limit: 5,                   // 5 request/IP/15p
  keyGenerator: (c) => c.req.header('x-forwarded-for') ?? 'unknown'
})

app.post('/api/auth/ensure-auth-user', authLimiter, async (c) => {
  // ... cũng nên normalize 404 và 403 thành 1 response chung để chống enumeration:
  if (!employee || !employee.is_active) {
    return c.json({ error: true, message: 'Không thể bootstrap tài khoản' }, 400)
  }
})

// Quan trọng hơn: cân nhắc xóa endpoint public này hoàn toàn nếu không cần thiết.
// Hoặc require pre-shared bootstrap token (admin cấp tạm).
```

### 🟠 [16] HIGH — BROKEN-ACCESS-CONTROL tại `src/lib/supabase-protected-storage.ts:8-26`

**Mô tả ngắn:** Supabase JWT `access_token` + `refresh_token` lưu trong `localStorage`. Còn có thêm backup `sb-session-backup` TTL 7 ngày. localStorage truy cập được bởi mọi JS cùng origin → nếu có lỗ hổng XSS bất kỳ → token theft + session lasting 7 ngày.

**Tác động**

Token theft qua XSS là vector phổ biến nhất account takeover. Backup token 7 ngày khuếch đại hậu quả: kể cả user logout, attacker có thể replay token từ backup. Rule `vbsec` flag rule này là **defense-in-depth**: nếu sanitize-html (finding [F-XSS-1] phía sau) bị bypass → trực tiếp lấy được token.

**Cách sửa**

```typescript
// Long-term fix: chuyển refresh_token sang httpOnly cookie (backend-only access)
// Quick mitigation:
// 1. Bỏ backup 7 ngày — risk > benefit
// 2. Đảm bảo CSP header chặt: Content-Security-Policy: default-src 'self'; script-src 'self'
// 3. Audit toàn bộ v-html (đã check ở finding [F-XSS-1]) + innerHTML usage
```

## ĐÃ ĐẠT

- ✓ **SQL-INJECTION** — Tất cả Supabase calls dùng parameterized PostgREST methods (`.eq`, `.in`, `.ilike`, `.or`, `.range`). Không có `supabase.rpc()` build name/params từ template string. PL/pgSQL functions không dùng `EXECUTE format('%s', user_input)`.
- ✓ **CSRF** — JWT Bearer auth only; không dùng cookie session → CSRF không applicable.
- ✓ **CORS (server-side)** — `server/index.ts` dùng explicit origin allowlist (không `*`), `credentials:true` pair với restricted origins, không regex bypass.
- ✓ **PATH-TRAVERSAL** — `guides.ts` validate `filePath.includes('..')` trước Supabase Storage call. Không có filesystem operations với user input.
- ✓ **UNRESTRICTED-FILE-UPLOAD (admin-guides)** — `guides.ts` validate MIME type + 10MB cap, convert via `sharp` trước store.
- ✓ **RACE-CONDITION (server)** — Inventory updates dùng atomic PostgreSQL RPC (`fn_issue_cones_with_movements`, `fn_receive_delivery`) với internal locking. Idempotency log với `idempotency_key` UUID.
- ✓ **JWT-NONE-ALGORITHM (server)** — `auth.ts` explicit whitelist `algorithms: ['HS256']` hoặc `['RS256','ES256']`. None alg không thể dùng.
- ✓ **COMMAND-INJECTION** — Không có `child_process.exec/spawn` với user input. Scripts shell đều quote biến đúng cách.
- ✓ **INSECURE-DESERIALIZATION (eval/Function)** — Không có `eval()` hoặc `new Function()` ở backend lẫn frontend.
- ✓ **MASS-ASSIGNMENT (routes)** — Tất cả state-changing routes dùng explicit field allowlists (Zod schemas hoặc manual updateData objects). KHUYẾN NGHỊ: thêm `.strict()` để bắt typo (xem finding MEDIUM).
- ✓ **WEAK-PASSWORD-HASHING** — Password hashing delegated to Supabase Auth (bcrypt). Không có MD5/SHA1.
- ✓ **SLOPSQUATTING** — Các import (`hono`, `jose`, `zod`, `@supabase/supabase-js`, `isomorphic-dompurify`, `dayjs`, `quasar`) đều là package phổ biến, không có typosquatting candidate.
- ✓ **IDOR** — Model permission-based (không ownership-based) là cố ý theo architecture. DB lookups validate resource existence + permission check ở `requirePermission()`.
- ✓ **XSS (Vue components)** — `v-html` chỉ dùng cùng `sanitizeHtml()` (DOMPurify). Không có `innerHTML`/`outerHTML`/`document.write`. AppEditor (Tiptap) là input-only. Vue templates `{{ }}` auto-escape. CSS `style` attr issue đã raise riêng ở MEDIUM.
- ✓ **MASS-ASSIGNMENT (components)** — Không component nào emit object chứa privileged fields (`is_admin`, `is_root`, `role_id`, `permissions`).
- ✓ **BROKEN-ACCESS-CONTROL (admin gates)** — `ResultsDetailView.vue`, `GuideCard.vue`, `phan-quyen.vue`, `announcements.vue` đều có `isAdmin()`/`checkIsRoot()` gate hoặc `requiresRoot: true`.
